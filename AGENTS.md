# AGENTS.md (Certification Anticheat)

## What this is

- MV3 Chrome extension. The UI is the action popup: `manifest.json` points it at `camera.html`, which loads `sniff.js`, `anticheat.js` and `camera.js` as scripts. There is one small background service worker, `worker.js`, that handles consent/start messages and unions the exam labels the auto-detector reports (see below).
- Camera logic is in `camera.js`: `getUserMedia` → MediaPipe `FaceLandmarker` (VIDEO mode, 1 face, blendshapes) → boxes around the eyes, open/closed from `eyeBlinkLeft`/`eyeBlinkRight`.
- Anti-cheat logic is in `anticheat.js` (popup panel) and `tracker.js` (a script injected on demand into the one watched tab). Exam detection lives in `sniff.js`, shared by the popup (script tag), the auto-detector `detect.js` (content script) and the worker (`importScripts`).
- Fully offline by design. `vendor/mediapipe/` (bundle + WASM + Apache-2.0 LICENSE) and `models/face_landmarker.task` are vendored. Never switch to CDN/npm imports or remote URLs — MV3 CSP blocks remote code.
- Same page opens in a larger window via `?window=1` for the first-run permission prompt.

## Project direction (why it exists)

- This repo is the seed of a Chrome extension based anti-cheat system for online certification quizzes/exams.
- Planned features are the usual anti-cheat controls: enforced full screen and similar. Add them as separate, clearly-scoped features; the camera is only one signal.
- Shipped anti-cheat signal: the popup can watch one tab and count how many times that tab is hidden or its window loses focus (tab/app switches). That is `anticheat.js` + injected `tracker.js`.
- The camera feature is an experiment: use the device camera to notice when the candidate looks away from the screen (e.g. glancing at a phone to cheat). Today that means eye-landmark boxes, open/closed state, and a crude iris-position heuristic (mesh landmarks 468/473 inside each eye's contour box) — a fixed-threshold guess with no per-user calibration, not gaze tracking. Describe it that way.
- Keep the honest framing: a prototype attention check, not a reliable proctoring system. Future anti-cheat work should not make the README over-claim accuracy.

## Run / verify

- No `package.json`, build, lint, or test scripts. Don't add a bundler or package manager; the folder is loaded raw.
- `chrome://extensions` → Developer mode → Load unpacked → repo root. After editing, click Reload on the extension card, then reopen the popup (Chrome caches the popup page/module).
- Manual verification: open the popup, right-click inside it → Inspect for console output (GPU fallback warning, detection errors, tracker errors). Check boxes, badge text, green/amber states, and that the white mesh dots follow the face and turn yellow then red as the eyes move off centre; hold a side or down glance until the mesh is red and the badge says "looking away", then check a blink or a quick glance does not, and that turning the **Overlay** toggle off hides the dots and boxes in the popup and, through session storage, in the on-page preview while the badge stays live and look-aways still count. For anti-cheat, track a normal web page, close the popup, switch tabs/apps a few times, then reopen the popup and check the total; look away at a phone for ~2 s and check the total moves once with `looked away` beside it, that reopening the popup does not add one, and that the camera toggle off writes nothing. The camera preview should appear above the bubble (after camera access has been granted once); switch away and back to confirm it resumes. For the suggestion modal, open a quiz page on one of the supported training hosts and wait a moment (no popup needed), or open the popup on any exam-looking page; then right-click the page → Inspect to see `prompt.js`. Worker errors show up on `chrome://extensions` → the extension card → **service worker** (Inspect views).
- To re-test first-run permission: reset camera permission for `chrome-extension://<id>/` in Chrome site settings.

## Key behavior (don't accidentally break)

- Mirroring is split across two places: CSS flips only the video (`transform: scaleX(-1)`), not the canvas, so `eyeBox()` mirrors x as `(1 - x) * width`. Change both together or boxes drift off the eyes.
- Eye landmarks are hardcoded: `RIGHT_EYE = [33,160,158,133,153,144,163,7,246]`, `LEFT_EYE = [263,387,385,380,373,362,390,249,466]`.
- Blink: blendshape score `< 0.5` ⇒ open. `drawEye` draws green (open) / amber (closed) around each eye. `drawMesh()` draws all detection landmarks as small dots (one fill path, one colour, mirrored like the boxes) before the boxes; it is a point cloud, not a wireframe, because the vendored bundle does not export the mesh tesselation. Its colour is the gaze severity from `gazeColor(gaze.severity)`: white on screen, yellow at half the away threshold, red at the away entry threshold and flat red beyond (`GAZE_ON_COLOR`/`GAZE_MID_COLOR`/`GAZE_AWAY_COLOR`, two-stop lerp). Red is exactly the point that starts the look-away timer, so the counter only moves once the estimate reaches that threshold. The **Overlay** toggle in the footer legend (`#overlayToggle`, on by default) hides the dot mesh and the eye boxes; its value is the `chrome.storage.session` key `overlay` (missing ⇒ on), mirrored into every camera page through `chrome.storage.session.onChanged`, so the popup and the on-page preview cannot disagree. Badge, sampling and counting never read it. Badge wording and tones are set in `draw()`/`setBadge` (`idle`/`warn`/`live`), with `Eyes visible · looking away` when the gaze says so.
- Gaze is a heuristic in `camera.js`, constants at the top: `GAZE_ENTER_X 0.12` / `GAZE_ENTER_Y 0.10` to enter "away", `GAZE_EXIT_X 0.08` / `GAZE_EXIT_Y 0.07` to leave, `GAZE_SMOOTH 0.3` EMA, `GAZE_WARMUP_MS 2000` after `start()`, `AWAY_MS 1200` sustained before it counts. `irisOffset()` gives `h`/`v` of landmark 468 (right eye) / 473 (left eye) inside the eye's own contour bbox, averaged over both eyes, unmirrored (mirroring stays in `eyeBox()`/CSS). `gazeSeverity(h, v)` turns the smoothed offset into 0..1 (0 centred, 1 at the enter threshold, clamped above), kept in `gaze.severity` and reset by `resetGaze()`; `gazeColor()` maps it to the mesh colour. One count per episode via `awaySince`/`counted`, never per frame. Skip a sample when either blink blendshape is `>= 0.5`, when there is no face, fewer than 478 landmarks, or a degenerate box (`maxX <= minX` / `maxY <= minY`) — no face or no iris must never count. `clearAway()` (not `resetGaze()`) on a lost face, missing box, or a closed focus gate so time spent unfocused cannot bank into a count. The gate only blocks counting: sampling, the EMA and `gaze.severity` keep updating so the popup/window mesh and badge stay live. `resetGaze()` on `start()` (warm-up), `stopCamera()`, `restartCamera()` and `pagehide`.
- Only the tracked tab's preview may increment `lookAway`: `init()` keeps the token and tabId from the state it validated, and `countLookAway()` re-reads `anticheat`, requires `state.token === trackedToken` and `state.tabId === trackedTabId`, then writes only `lookAway` and `last`. Never create the state. Sampling is also gated on `isPreview` + `document.visibilityState === 'visible'` + a focus flag: an iframe's own `document.hasFocus()` is false unless the frame is clicked, so `tracker.js` posts `{ type: 'anticheat:focus', focused }` to it (on iframe load, `start`/`pause`/`resume`, and every `onStateChange`) and `camera.js` counts only while `focused` is true. That pauses counting while the popup is open; the popup/window camera still shows the live badge and mesh but never counts.
- Permission flow in `init()`: `navigator.permissions.query({name:'camera'})`; granted/null or `?window=1` → start; denied → blocked card with settings link; unknown → card that calls `openWindow()`.
- `openWindow`/`openSettings` use `chrome.windows.create` / `chrome.tabs.create` when present, with `window.open`/no-op fallbacks. No manifest `permissions` are needed for these; don't add broad permissions.
- Camera failures are mapped by `DOMException.name` in `handleCameraError` (NotAllowed/Security → blocked, NotFound/Overconstrained → no camera, NotReadable → busy). Add new cases there, not in `start()`.
- The header **Camera** toggle (`#camToggle`) enables/starts the camera via `enableCamera()` and turns it off via `stopCamera()`, which releases the stream, closes the landmarker, clears the canvas, and shows the off card. Don't persist the toggle in storage; closing the popup already releases the camera.
- `start()` is async and cancellable via the `session` counter: toggling off while the camera or detector is still loading must not leave a live track or landmarker behind.
- Detection loop is `schedule(id)`: a `setTimeout` poll (100 ms visible, 1 s hidden), not `requestVideoFrameCallback`, because hidden or occluded windows stop presenting frames and that loop never recovers. `stopLoop()` invalidates the pending timer via `loopToken`. `resumeCamera()` runs on `visibilitychange`, window `focus`, and `chrome.windows.onFocusChanged`; it retries a failed `start()` while `wanted` is set and otherwise resumes playback/reacquires the stream, so the camera returns without the user touching the extension, even while the camera page stays minimized. `tick()` and the track `ended` event also reacquire a dropped stream. Canvas is sized from `videoWidth`/`videoHeight` on video `resize` and after play. `starting`/`running` guard against double starts.
- `pagehide` stops tracks and closes the landmarker. Any new long-lived resource must be cleaned up there.
- WASM and model paths use `new URL(..., import.meta.url)` so they resolve in both popup and window. Keep them relative.
- Anti-cheat state is one object under `chrome.storage.session` key `anticheat`: `{ tabId, windowId, title, url, count, lookAway, last, token, startedAt }`. `last` is `null` or `{ kind: 'switch' | 'away', at }` and drives the "what just happened" line. One object means one watched tab; `worker.js` stops the previous tracker before storing the new one. Never keep a list of tabs without a product decision.
- `anticheat.js` and `worker.js` call `chrome.storage.session.setAccessLevel({ accessLevel: 'TRUSTED_AND_UNTRUSTED_CONTEXTS' })` so the injected content script can read/write the counter. Do this before injecting; otherwise tracker writes fail silently.
- Injection uses `chrome.scripting.executeScript({ files: ['tracker.js'] })`, which needs the `scripting` permission **plus host permission or `activeTab`**. `manifest.json` declares `host_permissions` for the same 22 training hosts as `content_scripts[0].matches`, so the auto-prompt path (no toolbar click, therefore no `activeTab` grant) can inject there; `content_scripts.matches` alone would not, and Start would fail with `{ ok: false }` and the modal's "open the extension and press Start" line. Every other page is still reached with `activeTab` from the toolbar click. It only works on `http(s)` pages the user is currently on; keep `canInject()` in sync if that changes. The worker does the inject now, on behalf of both the popup and the modal.
- `anticheat.js` `paint()` shows one total (`#totalCount`) = `(state.count || 0) + (state.lookAway || 0)`, with an inline `#lastCause` from `state.last` wording the trigger (`tab / app switch` or `looked away`, hidden when `last` is null). The stored shape is unchanged — `count`, `lookAway` and `last` stay separate and the sum is display-only — so `worker.js` and `camera.js` were not touched. The label is persistent, not a flash: no timers, `last` is replaced by the next increment and cleared by `undo()`/Stop.
- `tracker.js` counts one departure per away episode, not one per event: `visibilitychange`, `blur`, `focus`, and `pageshow` all call `onStateChange()`, which only increments when the tab goes from focused/visible to hidden/unfocused and only resets when it comes back. `count()` also stamps `last: { kind: 'switch', at }`, `undo()` clears it.
- The same counts are mirrored on the watched page as a bubble (`#eye-check-anticheat`, fixed bottom-right, `pointer-events: none`) inside a shadow root, so page CSS cannot restyle it. `tracker.js` paints it from storage on `start` and after every successful `writeState`, and one `chrome.storage.session.onChanged` listener repaints it when the camera preview writes a look-away (removed in `dispose()`); `stop()` and `dispose()` remove it. Repaint is gated on `enabled` so a late write cannot recreate it after Stop. The bubble is one line, `N events · cause` (same total and wording as the popup, built with `textContent`), with no timer: the cause stays until `last` changes or is cleared. Each rise of the total plays three fast, high-pitched Web Audio pings (`ding()`: `PING_HZ`/`PING_GAIN`/`PING_GAP` at the top of `tracker.js`, fixed and deliberately loud with no volume control): synthesised, no audio files, an `AudioContext` created lazily and primed on the first page gesture (`pointerdown`/`keydown`); it is deduped against the previously painted total, so one increment pings once (even though `writeState` and the storage change both paint it) and a reattach never pings. A page the user has never clicked can stay silent under Chrome's autoplay policy, and any audio failure is swallowed so counting never depends on it. An element in fullscreen covers the bubble (top layer).
- Above the bubble, `tracker.js` embeds `camera.html?preview=1&token=…` as a 160×120 iframe, so the camera runs in the watched tab and comes back with the tab's focus. `camera.html` must stay in `web_accessible_resources` (the page loads the frame); `camera.js` only starts when the token matches the stored state, and `anticheat.js` skips its panel when `?preview=1`. The iframe is revealed on `load` so its full panel chrome never flashes.
- The extension popup steals focus, so the tracker must be paused while the popup is open or checking the counter would inflate it. `anticheat.js` sends `anticheat:pause` and holds a `chrome.tabs.connect` port; the port disconnecting is the reliable resume signal. `tracker.js` also undoes an increment caused by the popup's own blur in the same window (`popupBlur` / `undo()`), and waits 250 ms after resume before deciding a switch is real.
- `tracker.js` must stay idempotent (`globalThis.__eyeCheckTracker`) because re-injection happens when a reloaded page needs reattaching. `start` re-enables an existing tracker instead of relying on a fresh injection.
- If the watched tab navigates/reloads while the popup is closed, the injected script is gone. Opening the popup on that tab pings it and re-injects, keeping the stored count. `worker.js` must not grow a `chrome.tabs.onUpdated` listener to fix this: reattaching needs the popup's port and detection needs `activeTab`.
- `chrome.tabs.onRemoved` and the tab-exists check in `refresh()` clear stale tracking state when the watched tab is closed.
- `sniffExam()` lives in `sniff.js` together with `SIGNAL_WEIGHTS`, and all three consumers share those bindings: `camera.html` loads it with a script tag, `worker.js` calls `importScripts('sniff.js')` (never switch the manifest to `"type": "module"`), and `detect.js`/`prompt.js` share the isolated-world global. It is passed by reference to `executeScript`, so it must stay self-contained and return short reason labels only — never page text. It returns `{ reasons }` with no score: the weights live next to the labels, and each caller unions reasons, drops unknown labels and sums the weights itself. `exam heading` reads the document title and real heading elements (`h1`, `h2`, `h3`, `h4`, `legend`, `[role=heading]`, first 200), or a "question N" in the body text — never arbitrary body text, because a training host's sidebar lists its quiz section on every page; `exam URL` only counts alongside question-shape evidence (`controls >= 3`, `question counter`, `timer` or that question numbering), so `training platform` + `exam URL` cannot reach the threshold on its own. A practice/sample/demo/pretest/guide/faq/help URL or title filters the contextual reasons (`exam URL`, `exam heading`, `training platform`) out instead of subtracting. Offered only at `score >= 3`. Detection is wrapped in try/catch and never starts anything.
- Auto-detection needs no toolbar click, because `manifest.json` declares `content_scripts` for the 22 training hosts already listed in the `training platform` regex (`sniff.js`, `detect.js`, `prompt.js`, `all_frames: true`, `document_idle`), and `host_permissions` lists those same 22 hosts so the tracked inject is allowed there too. `detect.js` sniffs its own frame, keeps only labels that exist in `SIGNAL_WEIGHTS`, and posts `{ type: 'anticheat:frame-reasons', reasons }` only when the `location.href` plus that label set changed (the url is in the key because an SPA quiz view can repeat the same labels; an empty snapshot clears the baseline). A quiz view is usually rendered after the SPA route changes, so it re-sniffs on `pushState`/`replaceState`/`popstate`/`hashchange` and again at 500/2000/5000 ms — no MutationObserver, interval or `requestAnimationFrame` loop. (The pushState patch only sees calls that reach the isolated world's own `history` wrapper, so in-app route changes are best effort; `popstate`/`hashchange` and the delayed rescans are what usually catch them.) It never starts anything, writes storage or touches the camera. Sites outside those hosts still need the popup click (`activeTab` → `executeScript`), because there is no `<all_urls>`; a new host must be added to all three — the `training platform` regex in `sniff.js`, `content_scripts[0].matches`, and `host_permissions` in `manifest.json` — and they must stay identical, because a mismatch silently breaks auto-start on that host.
- The exam suggestion is a centered modal drawn on the page by `prompt.js`, not a row in the popup: the popup closes the moment the user clicks the page, so the offer has to live in the page. It is declared as a content script in every frame and returns early unless `window.top === window`, so an iframe never draws one; `maybeSuggest()` in the popup and `frameReasons()` in the worker both send `{ type: 'anticheat:show-prompt', reasons }` to it. `prompt.js` is idempotent (`globalThis.__eyeCheckPrompt`), renders `#eye-check-prompt` in a shadow root over a dimmed backdrop, and stays interactive (`pointer-events: auto`, unlike the bubble). `anticheat:close-prompt` removes it. Its only actions are **Start monitoring** and **Not now** (Escape and a backdrop click also dismiss). **Not now** only closes the modal for that page visit: nothing is stored, so the offer comes back on a later visit to a quiz page in the same tab — a new document or a new URL. The popup keeps no prompt or dismissal state: `paint()` never mentions the modal, and the panel's manual Start button stays as the fallback.
- `worker.js` handles consent/start and aggregates the auto-detector's frame reasons, nothing else. Message contract: `{ type: 'anticheat:consent', choice: 'start' | 'dismiss' }` from the modal (uses `sender.tab`), `{ type: 'anticheat:start-tab', tabId }` from the popup button (resolves the tab with `chrome.tabs.get`), and `{ type: 'anticheat:frame-reasons', reasons }` from `detect.js`. It writes the `anticheat` state, injects `tracker.js` and sends `anticheat:start`. For frame reasons it keeps an in-memory `Map` keyed by `tabId` (`{ url, documentId, reasons: Set, prompted }`), starts a fresh entry when `sender.tab.url` or `sender.documentId` changes (a reload or a navigation is a new visit that can be offered again, while another frame of the same document cannot re-show a modal the user just dismissed), drops unknown labels, and at `score >= 3` sends `anticheat:show-prompt` with the union — unless that tab is already the tracked one or the entry was prompted before (the flag is set before the message so two frames cannot double-show). It must never gain timers, `chrome.tabs.on*` listeners, polling or page access of its own: none of that works in a service worker without host permissions, and detection belongs to the popup and the content scripts.
- After a modal-initiated start the worker sends `anticheat:resume` right after `anticheat:start`, because there is no popup port that could later resume the tracker. Do not send it on the popup's `anticheat:start-tab` path: there the popup's `keepAlive()` port disconnects on close and resumes the tracker, and an early resume would count the popup's own blur.

## Gotchas

- MV3 CSP requires `'wasm-unsafe-eval'` for MediaPipe (already set in `manifest.json`).
- Popup width is fixed at 360px in CSS; `html.window` (added from `?window=1`) widens it to 620px. Window size lives only in `openWindow` (620×780).
- Boxes mean eye landmarks were found, not that the eye is unobstructed; fixed 0.5 threshold. Limitations are documented in README — don't over-claim detection accuracy.
- No analytics or network calls. `chrome.storage.session` holds only the `anticheat` counter state and the `overlay` boolean, and is intentionally in-memory and cleared on restart. Keep it that way. It is the only storage the extension uses — `chrome.storage.local` is no longer written; an old profile's `anticheatSites` allowlist from a removed feature is ignored, not migrated or cleaned up.
